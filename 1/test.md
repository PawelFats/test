### Перечислите все проблемы, которые вы видите в данном коде:

    class Foo
    {
    public:
        Foo(int j) { i=new int[j]; }
        ~Foo() { delete i; }
    private:
        int* i;
    };

    class Bar: Foo
    {
    public:
        Bar(int j) { i=new char[j]; }
        ~Bar() { delete i; }
    private:
        char* i;
    };


    void main()
    {
        Foo* f=new Foo(100);
        Foo* b=new Bar(200);
        *f=*b;
        delete f;
        delete b;
    }

---

### Ответ:

1.	По стандарту C++ функция main должна возвращать целочисленный код завершения (int), чтобы сигнализировать об успешном/неуспешном завершении программы.
2.	Если класс Foo используется полиморфно (удаление через указатель на базовый класс), у него должен быть виртуальный деструктор. Без этого удаление объекта через Foo* вызывает неопределённое поведение и потенциальные утечки/ошибки. То же применимо к другим базовым классам, используемым полиморфно.
3.	При некорректном копировании/присваивании объектов возникают две серьёзные проблемы:
3.1.	Если происходит копирование производного объекта в базовый, часть данных производного класса теряется — копируется только часть базового класса.
3.2.	При поверхностном копировании указателя два объекта начинают указывать на одну и ту же область памяти — это приводит либо к утечке, либо к двойному освобождению памяти.
4.	В результате предыдущего пункта возможны двойное освобождение памяти или утечка.
5.	Имена переменных должны быть осмысленными и различаться в разных классах; одинаковые имена вроде i в нескольких местах приводят к путанице.
6.	после delete полезно присвоить указателю nullptr, чтобы избежать висячих указателей.
7.	нет проверки на то, была ли выделена память оператором new
8.	Для освобождения памяти, выделенной через new[], необходимо использовать delete[], а не delete.
9.	Для корректного создания объектов Foo* b = new Bar(200); наследование должно быть публичным: class Bar : public Foo.
10.	Если у базового класса Foo нет конструктора по умолчанию, конструктор производного класса Bar обязан явно вызвать подходящий конструктор Foo в списке инициализации.
